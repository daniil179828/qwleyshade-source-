## Загрузки с GitHub — текущая версия

Все мобильные кнопки в `public/index.html` и `public/qwleyshade1.html` направлены на `/api/download?platform=ios` или `/api/download?platform=android`.

- IPA: https://github.com/daniil179828/ipaqwleyshade
- APK: https://github.com/daniil179828/apkqwleyshade

Обработчик читает текущий HEAD основной ветки через GitHub API, рекурсивно ищет файл `.ipa` / `.apk` и перенаправляет на скачивание именно файла, а не ZIP репозитория и не страницу GitHub. Название и вложенную папку можно менять, код сайта менять не нужно. Название основной ветки тоже не зафиксировано.

**Держите в каждом репозитории только одну актуальную сборку соответствующего расширения.** При обновлении удаляйте старый APK/IPA и добавляйте новый, желательно одним коммитом. Если файлов несколько, обработчик выдаёт понятную ошибку 409, а не угадывает актуальную версию по имени. Старые сборки можно хранить в Releases или другой ветке. Если файла нет — ошибка 404.

Список файлов кешируется сервером на 30 секунд для снижения расхода GitHub API. После обновления сборки подождите до 30 секунд. Ошибки не кешируются. HTTP-перенаправления не кешируются браузером.

Оба присланных репозитория используют Git LFS. Используется ссылка `github.com/.../raw/<commit>/<path>?download=1`, которая корректно перенаправляет на настоящий LFS-файл. Простая raw.githubusercontent.com-ссылка могла бы отдать маленький текстовый указатель вместо установщика. Скачивание привязано к найденному коммиту, чтобы одновременное переименование файла не ломало ссылку. Большой файл не передаётся через Vercel Function.

Windows-загрузка оставлена без изменений.

## Публикация на Vercel

1. Замените файлы в существующем проекте содержимым архива. Сохраните структуру: `api/` и `package.json` лежат в корне проекта, HTML и ресурсы — в `public/`.
2. Framework Preset: Other. Output Directory: public. Серверная функция `api/download.js` обязательна: одного статического HTML недостаточно.
3. Vercel Blob больше не используется. `BLOB_READ_WRITE_TOKEN` и пакет `@vercel/blob` не нужны. Удалять само старое хранилище не требуется.
4. Для публичных репозиториев GitHub token необязателен. Без авторизации GitHub API обычно ограничен 60 запросами в час на исходящий IP; один некешированный поиск использует два запроса. При посещаемом сайте рекомендуется добавить серверную переменную `GITHUB_TOKEN` с доступом на чтение этих репозиториев. Токен не добавлять в HTML или исходники. После изменения переменных выполните Redeploy.
5. Выполните Redeploy и проверьте кнопки iOS/Android на своём домене. GitHub LFS должен оставаться доступным и иметь достаточную квоту для скачивания.
